# Attachment evidence intake

1. Inventory the bounded attachment set with file type, size, hash, supplied title, and exclusion status.
2. Use the format-aware runtime reader. Inspect rendered pages, slides, sheets, diagrams, screenshots, and
   annotations when position, grouping, cropping, or visual hierarchy affects meaning.
3. Extract one atomic finding per claim. Give it a stable local ID and exact page, slide, section, cell,
   element, timestamp, or image-region locator.
4. Record the source's claim, evidence class, date, author when known, interpretation, and search hints
   separately. Do not turn hints into facts.
5. Start implementation or operational claims as unverified. Link supporting and contradicting source,
   code, configuration, runtime, or test evidence before changing status.
6. Preserve confirmed, partially confirmed, contradicted, outdated, not applicable, and unresolved outcomes.
   Never delete a contradiction merely because a preferred conclusion has stronger support.
7. State unreadable content, extraction limits, missing pages, unsupported media, and visual-inspection limits.

Artifact generation or regeneration belongs to the runtime document, presentation, spreadsheet, or PDF
capability and any project-specific template. It is not part of attachment evidence analysis.
