# Contracts, data, and batch analysis

- For WSDL/XSD/SOAP or other contracts, inventory operations, messages, schemas, imports, versions,
  bindings, endpoints, faults, optionality, namespaces, and generated/client mappings.
- For databases, trace exact reads/writes, tables/views/procedures, keys, transactions, ordering,
  concurrency, defaults, constraints, and error behavior. SQL names alone do not establish semantics.
- Record important data structures, nesting, sizes/types, optionality, repetitions, overlays/unions, key
  fields, validation, transformations, and cross-boundary semantic mismatches.
- For batch, record scheduler/trigger, ordered steps, inputs/outputs, checkpoints, restartability,
  idempotency, partial failure, reconciliation, and downstream dependencies.
- For cross-system flow, record the boundary identifier, direction, payload, protocol, ownership,
  timing, retry behavior, and evidence on both sides. Keep one-sided assumptions visible.
