# Visual pattern guidance

This small canonical collection describes reusable information structures without imposing a brand or
aesthetic. Project references and project brand rules take precedence over these neutral patterns.

Each pattern records its best use, inappropriate uses, information capacity, interaction opportunities,
responsive behavior, and accessibility considerations. Promote additional patterns only after repeated,
high-quality project evidence; never copy client branding or proprietary visuals into this collection.

Current bounded patterns:

- `timeline.md` — grouped phases, milestones, dependencies, and decision gates;
- `cluster.md` — capability or concept grouping with explicit relationships;
- `evidence-chain.md` — claim-to-source-to-implication traceability;
- `system-landscape.md` — domains, applications, external systems, and integrations;
- `component-architecture.md` — solution boundaries, components, interfaces, and dependencies;
- `class-diagram.md` — focused object/domain structure and relationship notation;
- `er-diagram.md` — layered entity/key/cardinality views for databases;
- `sequence-diagram.md` — ordered participants, branches, and failures;
- `data-flow-diagram.md` — source, transformation, store, destination, and lineage views.
