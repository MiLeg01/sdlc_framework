# Canonical skills

| Skill | Use | Do not use |
|---|---|---|
| `accessibility-review` | Audit completed UI journeys across automation, keyboard, focus, reflow, contrast, motion, semantics, and assistive evidence | Claim accessibility from a screenshot, scanner-only pass, or unavailable test surface |
| `anonymize-data` | Minimize and deterministically protect structured data with field-scoped drop, redaction, or stable-token rules | Claim legal anonymization, guess identifiers in arbitrary prose, or skip residual-risk review |
| `generate-synthetic-fixtures` | Generate committed test fixtures from a reviewed allowlist specification, keeping load-bearing signal while every identity value is approved | Transform a structured dataset for analysis, purge sensitive data already in history, or scrub prose |
| `initialize-project` | Adaptively bootstrap empty/nearly empty or existing workspaces, including persisted client-sector, locale, and output-specific delivery policies | Bulk-copy the commons, overwrite established projects, or impose durable machinery on a tiny task |
| `continue-project` | Resolve the next lifecycle step from canonical project state or a requirement/specification reference | Bypass approval, OpenSpec, TDD, dependency ordering, or project blockers |
| `review-for-commons` | Compare an active project's proven patterns with commons and write a sanitized changeset proposal | Promote, install, or mutate commons; globalize speculative or one-off behavior |
| `promote-to-commons` | Revalidate and implement only explicitly selected reusable capability candidates in canonical commons | Discover candidates, infer approval from a review, mutate source projects, or bypass evals and provenance |
| `search-external-capabilities` | Search configured official, curated, and community sources for relevant external capabilities | Install, trust, copy, execute, or promote discovery results automatically |
| `review-external-capability` | Deeply review one revision-pinned external capability for provenance, license, security, overlap, and targeted ideas | Execute the package, copy unknown-license content, or promote directly |
| `deep-research` | Frame, gather, evaluate, synthesize, and trace topic research for decisions or downstream artifacts | External capability discovery, unsupported invention, or a trivial lookup |
| `coordinate-parallel-agents` | Partition independent work into exclusive worker contracts and centrally validate and integrate isolated outputs | Parallelize overlapping writes, shared decisions, canonical state, or tiny tasks |
| `design-frontend-architecture` | Define routes, modules, rendering, state, interfaces, failure states, and design-guide consumption | Choose visual styling, sequence delivery, or invent unsupported target decisions |
| `design-test-strategy` | Map delivery risks to the smallest credible test-layer portfolio | Mandate every layer or use coverage percentage as behavioral proof |
| `inventory-codebase` | Establish deterministic scope, classification, hashes, and batches | Infer behavior from paths or replace source analysis |
| `maintain-project-memory` | Persist and selectively retrieve hierarchical evidence-backed project knowledge, checkpoints, and context packages | Store conversations/hidden reasoning, create a second truth store, or use memory as original evidence |
| `manage-project-delivery` | Govern cross-workstream delivery through dependency-aware health, RAID, decisions, actions, and evidence-based status | Implement work items, replace detailed planning, or mutate external trackers without authorization |
| `migrate-code-with-evidence` | Migrate one bounded read-only source slice into an isolated target with traceability and strict TDD | Bulk prompt-translate, overwrite source, embed credentials, or equate generation with parity |
| `mutation-testing` | Evaluate whether tests would actually detect defective implementation behavior, classify surviving mutants against specifications, and harden tests behaviorally | Run during RED, treat mutation score as the only gate, or distort correct production code to kill a mutant |
| `deconstruct-problem-first-principles` | Establish what the problem actually is and at what level to answer it, before planning or implementing | Plan the work itself, research a topic, review an existing design, or handle a fully specified change |
| `plan-work` | Build evidence-linked, dependency-aware executable plans with ownership, validation, and recovery | Turn unresolved decisions into assumptions or report planned work as complete |
| `protect-git-work` | Preserve dirty-state ownership, verified checkpoints, safe integration, and exact recovery | Erase unknown work or rewrite shared history without authorization |
| `analyze-legacy-system` | Analyze the complete configured legacy system by default through inventory-backed bounded slices, synthesis, coverage, and resumable fan-in | Stop after the first slice, silently omit source, or design target behavior from filenames/comments |
| `derive-modernization-requirements` | Turn evidence into deduplicated requirements and scenarios | Promote recommendations or memory summaries into observed facts |
| `execute-safe-change` | Bind authorization, dry-run, execute, verify, and recover consequential state changes | Mutate vague targets or use a dry run that can still write |
| `estimate-adm-modernization` | Scope, calibrate, aggregate, and independently review outcome-based modernization effort | Convert source size to effort or publish unreviewed ranges as schedule or cost |
| `frontend-design` | Define and implement intentional product UI hierarchy, composition, states, and responsive behavior | Style one-off narrative artifacts or substitute design for downstream validation |
| `forecast-project-financials` | Reconcile baseline, actuals, remaining-work drivers, scenarios, EAC, variance, and margin for project delivery | Provide statutory accounting, tax, investment advice, or unreviewed commercial approval |
| `polish-html-artifact` | Improve the visual execution of a complete HTML artifact while preserving its structure, narrative, claims, brand authority, and interaction model | Invent content, redesign information architecture, establish a client brand, or replace independent validation |
| `audit-delivery-traceability` | Independently audit source-to-verification chains | Repair state while acting as auditor |
| `implement-ready-slice` | Select and deliver one dependency-ready accepted slice with TDD | Implement blocked, unapproved, or externally owned work |
| `validate-work-item-assumptions` | Check read-only whether a previously filed item's claims about current state still hold, and return one materiality verdict | Decide whether the work proceeds, propose a revised approach, or edit the item |
| `specify-openspec-change` | Define or refine one OpenSpec change with behavior-first requirements, scenarios, design, and tasks before implementation | Implement first, duplicate an active change, or impose OpenSpec on unrelated or trivial work |
| `review-openspec-change` | Resolve ambiguity and assess an existing OpenSpec change for implementation readiness | Implement code or approve missing product decisions by assumption |
| `implement-openspec-change` | Deliver one approved OpenSpec change task by task with scenario, code, and test traceability | Implement an unapproved change or silently diverge when the specification is wrong |
| `verify-openspec-implementation` | Reconcile every material OpenSpec requirement and scenario with code, tests, and repository evidence | Fix implementation while claiming independent verification or rewrite specs to match code |
| `complete-openspec-change` | Validate, merge or intentionally skip deltas, archive the exact verified change, and confirm closure | Archive incomplete, invalid, ambiguous, or unverified work |
| `build-living-dashboard` | Instantiate the canonical read-only dashboard with owned-criterion traceability, bounded large registers, semantic brand roles, deterministic localization coverage, and hard lifecycle QA | Invent project-specific navigation, expand shared specifications cartesianly, claim validation without required QA, edit lifecycle truth, or hand-edit metrics |
| `create-branded-html-artifact` | Resolve official brand URLs into exact offline assets and one shared dashboard/presentation profile, then build evidence-aware client-specific HTML | Apply a generic AI theme, synthesize identity, hot-link assets, or clone a marketing site |
| `create-technical-diagram` | Select the right technical diagram, evidence model, format, decomposition, and destination | Create decorative visuals or invent architecture facts |
| `create-system-landscape-diagram` | Map systems, applications, actors, scope, lifecycle state, and evidenced integrations | Show internal component detail or infer integrations from proximity |
| `create-component-architecture-diagram` | Explain solution containers, modules, services, components, data ownership, and dependencies | Mix enterprise, component, class, and sequence levels on one canvas |
| `create-class-diagram` | Derive focused class/domain structure from selected code or approved design | Dump every type/member or present proposals as verified source |
| `create-er-diagram` | Derive keys, entities, relationships, join tables, and defensible cardinalities | Guess foreign keys or flatten a large schema into one unreadable view |
| `create-sequence-diagram` | Trace ordered participants, messages, alternatives, and failure paths | Use static relationships as proof of runtime ordering |
| `create-data-flow-diagram` | Trace sources, transformations, stores, destinations, and lineage | Substitute control flow or unsupported transformation guesses |
| `localize-client-artifact` | Localize one standalone HTML artifact for locale-aware German/English delivery with preserved design, state, identifiers, and evidence | Translate a sentence, redesign the artifact, call a runtime translation service, or maintain separate language files |
| `review-code-change` | Inspect complete diffs and return factual summaries plus evidence-backed severity findings | Implement while claiming independence or post externally without confirmation |
| `review-privacy-security` | Trace sensitive data and trust boundaries, challenge abuse paths, and report residual risk | Claim certification or implement fixes while acting as independent reviewer |
| `sales-storytelling` | Turn verified evidence into an audience-specific persuasive narrative, authored natively in the resolved client language and tone | Fabricate proof, force a generic template, or draft a known-German public-sector deck in English first |
| `test-driven-development` | Execute a directly invocable, evidence-recorded RED-GREEN-REFACTOR loop | Backfill tests after code and label the work TDD |
| `update-commons-presentation` | Refresh factual presentation data, classify narrative impact, and make only warranted story changes with visual QA | Hand-edit generated facts, redesign the presentation, or rewrite narrative for factual-only changes |
| `validate-visual-artifact` | Statically and visually verify a completed HTML/web artifact | Substitute visual review for initial design or business acceptance |

All skills are canonical, runtime-neutral capabilities and include scenarios under `evals/`. Technical
diagram skills preserve editable source and renderable output without mandating Mermaid, PlantUML,
Graphviz, or SVG for every use case.
